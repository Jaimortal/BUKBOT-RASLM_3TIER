QUERY NORMALIZATION LAYER DAY-BY-DAY PROMPT
Project: BukSU Rasa + Structured Retrieval Chatbot
Architecture: Rasa NLU + Query Normalization + Context-Aware Structured Retrieval

MAIN OBJECTIVE
Build a safe input-normalization layer that improves chatbot accuracy for:
- English typos
- Cebuano/Bisaya wording
- mixed English/Bisaya student phrasing
- common grammar mistakes
- domain-specific aliases for BukSU services, offices, documents, courses, and policies

IMPORTANT RULES
- Do not use an LLM.
- Do not translate full sentences.
- Do not aggressively autocorrect every word.
- Keep the original user message.
- Append normalized concepts only for known chatbot/domain words.
- Keep Rasa as the NLU layer.
- Keep the structured retrieval architecture.
- Test after every phase before proceeding.
- If a normalization rule is uncertain, prefer clarification choices instead of forcing an answer.

CORE DESIGN
User message:
"mamalhinay ko sa buksu unsa requirements?"

Search-normalized message:
"mamalhinay ko sa buksu unsa requirements transferee transfer student requirements documents need"

The UI should still display the original user message.
Only the router, entity resolver, and retrieval scorer should use the normalized search text.

HOW TO ADD NORMALIZATION DATA
Add exact phrase mappings to PHRASE_CONCEPTS:
"transfered student" -> "transferee transfer student"
"balhin nga student" -> "transferee transfer student"
"cor validaton" -> "cor validation"

Add token mappings to TOKEN_CONCEPTS:
"asa" -> "where location find"
"pila" -> "fee payment cost how much"
"unsaon" -> "how process steps"

Add root mappings to ROOT_CONCEPTS:
"balhin" -> "transferee transfer student"
"malhin" -> "transferee transfer student"
"dawat" -> "accept availability"

Add fuzzy roots only for highly important domain words:
"transferee"
"admission"
"enrollment"
"validation"
"library"
"requirements"

Avoid fuzzy matching generic words like "office", "student", "course", "pay", "go", or "id" because they can cause false matches.

DAY 4 - PHASE 2: CLARIFICATION SAFETY
Goal:
Prevent loops and bad single-option clarifications.

Rules:
- If there is only one clarification option and the payload equals the same topic, answer directly.
- Never show "Can you clarify if you mean X?" with only X as a choice when X can answer.
- If confidence is medium but options are unrelated, fallback politely instead of suggesting random topics.

QA:
- "student id" should answer student ID process.
- "borrow books" should not suggest INC.
- "transfered students" should not suggest borrow books.
- "how validate" should show validation choices unless memory clearly identifies COR or ID.
