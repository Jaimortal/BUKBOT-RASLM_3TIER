Knowledge Manager Admin UX Upgrade Prompt
=========================================

Role:
You are a senior full-stack AI chatbot engineer working on a Rasa + React + Express + JSON knowledge-base chatbot.

Main goal:
Improve the admin editing experience so non-technical admins can safely maintain knowledge data without accidentally breaking chatbot routing, memory, or retrieval.

Important rule:
Do this phase by phase. Do not proceed to the next phase until the current phase is implemented, debugged, and approved by the user.

Critical safety rules:
- Do not expose or allow normal admins to edit critical routing keys directly:
  - intent
  - context_topic
  - subject_key
  - subject_type
  - topic machine IDs
  - internal response object structure
- Admins should edit only human-safe content:
  - English response lines
  - Cebuano/Bisaya response lines
  - display_name
  - metadata phrases if intentionally exposed as "example questions"
  - images
  - map pins
  - map routes
  - choice labels/payloads only through safe UI controls
- Keep existing chatbot functionality working.
- Keep the old Super Intent JSON files as the storage layer for now.
- Do not remove the Super Intents system yet.
- Rename UI labels from "Super Intent" to admin-friendly names where possible, such as "Knowledge Category".
- Always create backups before JSON write operations.
- Always run tests after each phase.


Architecture direction
======================

Use this admin-facing hierarchy:

Knowledge Manager
  Knowledge Category
    Topic Group
      Answer Topic

Map this to JSON like this:

Knowledge Category:
  A JSON file inside rasa/actions/Supper Saiyan/
  Example: Oss_services.json

Topic Group:
  A parent object inside topics[]
  Example: PE Uniform

Answer Topic:
  A subtopic inside subtopics[]
  Example: PE uniform process

Machine-safe JSON should look like:

{
  "topic": "pe_uniform_process",
  "display_name": "PE uniform process",
  "intent": "pe_uniform_process",
  "context_topic": "process",
  "responses": {
    "en": [],
    "ceb": []
  }
}

Admin UI should display:
  display_name || formatted intent || formatted topic

Backend/router should continue using:
  intent
  subject_key
  context_topic
  topic machine ID
