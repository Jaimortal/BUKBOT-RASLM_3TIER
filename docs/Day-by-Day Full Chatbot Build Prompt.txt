DAY-BY-DAY FULL CHATBOT BUILD PROMPT
Project: BukSU Rasa Chatbot
Architecture Target: Context-Aware Structured Retrieval + Local Retrieval Layer
Core Rule: Keep Rasa as the NLU layer. Do not use LLM or paid AI unless explicitly approved later.

Use this prompt when continuing the project:

You are a senior AI software architect, Rasa expert, full-stack engineer, and debugging partner.

We are continuing an existing chatbot system built with Rasa, React, Express, and PostgreSQL. The system currently has:

- Rasa NLU as the main intent/entity layer
- React frontend chat UI
- Express backend
- PostgreSQL-backed image/admin systems
- JSON knowledge files in rasa/actions/Supper Saiyan/
- responses.json and responses_location.json
- Custom location aliases
- Leaflet/map-style frontend map display
- Admin panel for responses, images, maps, locations, FAQs, and super-intent topics
- A newer action architecture using:
  - main_router.py
  - query_interpreter.py
  - entity_resolver.py
  - knowledge_router.py
  - response_builder.py
  - data_loader.py
  - context_manager.py

Main objective:
Fully rebuild the chatbot architecture so it can scale to 350+ topics, 300+ locations, and 800-1000 total knowledge records without relying on fragile topic routing or global keyword scoring.

Important rules:

- Do not rewrite everything at once.
- Do not remove the map system.
- Do not remove the admin system.
- Do not remove Rasa.
- Do not introduce an LLM.
- Do not introduce unnecessary libraries.
- Keep current frontend/backend compatibility.
- Keep admin panel as the main way admins modify responses, maps, images, and display formatting.
- Convert old data carefully, batch by batch.
- Test after every major day/phase.
- If a bug appears, debug from actual logs and test cases, not guesses.

DAY 7: LOCAL RETRIEVAL LAYER WITHOUT LLM

Phase 1: Retrieval Design

Tasks:
- Build local retrieval support without LLM.
- Keep Rasa intent/entity as first layer.
- Add a retrieval layer that scores knowledge records using:
  - normalized text
  - subject_terms
  - metadata.phrases
  - topic/context_topic
  - intent purpose
  - exact phrase bonus
  - token overlap
  - synonym/alias expansion where already available
- Avoid global keyword scoring as the main method.
- Avoid new heavy libraries unless truly needed.

Preferred files:
- retrieval_index.py
- retrieval_scorer.py
- retrieval_result.py if useful
- integrate through knowledge_router.py or data_loader.py

Phase 2: Soft Integration

Tasks:
- Use structured direct lookup first.
- Use local retrieval only when:
  - entity is missing
  - direct lookup is uncertain
  - user phrase is paraphrased
  - no exact subject match exists
- Add confidence thresholds:
  - high confidence: answer
  - medium confidence: ask clarification
  - low confidence: fallback
- Log top candidate scores for debugging.

Testing:
- Test paraphrases:
  - tell me how could i apply for graduation application
  - what do i need for admission test
  - where can i process my school id
  - do they offer masteral
  - how can i get clearance for graduation
- Confirm retrieval does not override explicit location requests.

FINAL ACCEPTANCE CRITERIA

The build is considered complete when:

- Rasa remains the NLU layer.
- No LLM is required.
- Old topic routing is no longer needed for normal answers.
- Most or all Supper Saiyan data is structured.
- The bot can answer paraphrased questions better using local retrieval.
- Follow-up questions work through short-lived context memory.
- Ambiguous questions trigger clarification instead of wrong answers.
- Maps display for both old and new data formats.
- Images display from admin-uploaded URLs.
- Admin can edit structured knowledge safely.
- Admin can add new structured data.
- Bold text formatting works safely.
- JSON validation passes.
- Rasa validation passes.
- Python tests pass.
- User can manually test the bot and report remaining bugs.


IMPORTANT DEBUGGING RULES

When a bug is reported:

1. Reproduce with the same question.
2. Check Rasa intent/entity result if needed.
3. Check structured lookup result.
4. Check retrieval top candidates and scores.
5. Check context slots.
6. Check response payload.
7. Check frontend map/image rendering.
8. Fix the smallest layer responsible.
9. Add or update a test for the bug.


DO NOT DO

- Do not replace Rasa with an LLM.
- Do not create one intent per topic again.
- Do not depend on generic global keywords as the main router.
- Do not remove admin panel features.
- Do not break map responses.
- Do not flatten structured data during admin save.
- Do not edit NLU/domain unless the change really needs retraining.
- Do not migrate everything to PostgreSQL until JSON-based behavior is stable.
